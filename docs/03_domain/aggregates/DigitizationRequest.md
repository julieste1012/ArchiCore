> BP-012 Digitization is still marked Pending in BusinessProcesses. This document records the minimum technical model implemented under explicit assumptions; it is not a claim that the complete business process has been approved or delivered.

## Purpose

Track a digitization task for a documentary Folder and the metadata of the resulting digital assets. Binary content is stored independently through the object-storage abstraction.

## Aggregate Root

DigitizationRequest.

## References

- ProjectId: required identity of the operational project.
- FolderId: required identity of the physical/documentary folder being digitized.
- RequestedByUserId: required identity of the requester.
- StartedByUserId and CompletedByUserId: operator identities for the processing lifecycle.

Cross-aggregate ownership validation (Folder belongs to Project) belongs to the Application use case and must run in the same unit of work as persistence.

## Lifecycle

Requested -> Processing -> Completed.

- Create(projectId, folderId, requestedByUserId) creates the request and emits DigitizationRequested.
- Start(startedByUserId) is allowed only from Requested and emits DigitizationStarted.
- Complete(completedByUserId, files) is allowed only from Processing and emits DigitalFileGenerated for each stored object, followed by DigitizationCompleted.

No cancellation/rejection transition is introduced because the business process has not specified one.

## Digital file metadata

Each generated asset records:

- Opaque StorageObjectKey generated by the application/infrastructure layer.
- OriginalFileName.
- ContentType (MIME).
- SizeBytes.
- Sha256 checksum.
- PageCount.

The aggregate stores metadata and object references only. It does not store byte arrays or streams.

## Invariants

- ProjectId, FolderId and all actor IDs must be non-empty.
- A request can start only once.
- A request can complete only after it has started.
- At least one digital asset is required to complete.
- Storage object keys must be relative, unique within the request and free of traversal segments.
- Filename and content type must be present and bounded.
- SizeBytes and PageCount must be positive.
- SHA-256 must contain exactly 64 hexadecimal characters.
- A completed request is immutable through the implemented lifecycle methods.

## Domain events

- DigitizationRequested
- DigitizationStarted
- DigitalFileGenerated
- DigitizationCompleted

## Security and storage boundary

The application layer must validate file bytes and actual content type, compute checksum and page count, virus-scan where supported, generate object keys server-side and call IObjectStorage. No public upload/download API is implied by this domain specification. Authorization, retention, deletion, versioning and legal hold policies remain release blockers.
